# Coding Standards & Guidelines

To ensure consistency across code generated by different AI agents, we strictly enforce PSR-12 coding styles and modern PHP characteristics.

---

## 📋 1. Strict Typing

Every PHP class must begin with the strict types declaration:
```php
<?php

declare(strict_types=1);

namespace App\Services;
```

---

## 🏷️ 2. Type Hinting & Return Types

- Every controller method, service method, repository, and helper must define types for all arguments and return values.
- Use native nullable types (`?string`) or union types (`string|int`) where appropriate.
- Avoid using `mixed` unless strictly necessary.

```php
public function registerEmployee(array $data, int $roleId): Employee
{
    // Implementation
}
```

---

## 🔠 3. Naming Conventions

| Component | Standard | Example |
| :--- | :--- | :--- |
| **Model Names** | Singular StudlyCase | `OfficeShift` |
| **Table Names** | Plural snake_case | `office_shifts` |
| **Method Names** | camelCase | `getShiftDetails()` |
| **Variables / Properties** | camelCase | `$employeeRecord` |
| **Constants** | UPPERCASE_SNAKE | `STATUS_ACTIVE` |
| **Controller Names** | StudlyCase + Controller | `EmployeeController` |
| **Service Names** | StudlyCase + Service | `PayrollService` |
| **Repository Names** | StudlyCase + Repository | `UserRepository` |
| **Blade File Names** | kebab-case | `edit-details.blade.php` |

---

## 📝 4. Docstrings & Formatting

- Maintain documentation integrity.
- Do not write verbose comments for code that explains itself.
- Write docstrings for complex algorithms or business calculations using PHPDoc.
- Use `declare(strict_types=1);` and class separation lines consistent with PSR-12.
- Code blocks must use 4 spaces for indentation (standard PSR-12 setup for PHP).
